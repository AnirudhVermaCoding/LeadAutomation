# Decisions

Format: decision — why — alternative considered.

1. **Node runs TypeScript natively (type stripping, Node >= 24.12); no backend build step.** — Stable since 24.12/25.2; removes tsx/tsup and source maps. Costs: erasable syntax only, `.ts` import extensions. Docker copies the repo and installs prod deps (no `pnpm deploy`, which would put workspace packages under node_modules where Node won't strip types). — Alt: tsx at runtime, or tsdown bundle.
2. **TypeScript 6.0.x, not 7.0.** — typescript-eslint 8.71 supports `<6.1`; type-aware rules (`no-floating-promises`) matter for job code. — Alt: TS 7 without type-aware lint.
3. **drizzle-orm 0.45 (stable), not 1.0 RC.** `pg` driver shared with pg-boss. — Alt: 1.0 RC (move when stable).
4. **pnpm 12 pinned via `packageManager`, run through corepack.** — Current major. pnpm 10's auto-switch to 12 fails on this Windows machine, so use `corepack pnpm` or install pnpm 12 globally.
5. **Packages and tables are created in the milestone that first uses them.** — No empty scaffolding. Target layout is in CLAUDE.md.
6. **One process (`ROLE=all|api|worker`), compose = db + app; dashboard served by Fastify from M6.** — Smallest deployable unit for one VPS; same origin removes CORS for the dashboard. — Alt: separate api/worker/dashboard containers (split when load needs it).
7. **Better Auth instead of Supabase Auth.** — Lives in our Postgres, so mock mode needs zero external credentials.
8. **Tenant isolation = Postgres RLS + `withTenant()` as the single access path.** App connects as a non-owner role without BYPASSRLS; `systemDb` (owner) only under `apps/api/src/system/` (lint-enforced). — Alt: repository-only `where tenant_id = ?` (one forgotten filter leaks data).
9. **Human takeover is an orthogonal `ai_paused` flag, not a funnel state.** — Staff can book/complete a lead during takeover without resuming the AI; UI shows it as a status. — Alt: `human_takeover` state with a remembered resume state (blocks funnel moves).
10. **Business times come from the Clock; `created_at`/`updated_at` are bookkeeping.** — Keeps demo fast-forward and report math consistent.
11. **zod at boundaries via plain `parse` + Fastify error handler; no type-provider plugin.** — One less dependency.
12. **WhatsApp: Meta Cloud API direct first (FIRST_CLIENT_BSP = none).** BSP adapters wait for a client that uses one.
13. **Repo lives at `C:\dev\instantlead`, outside OneDrive.** — OneDrive sync fights node_modules and pnpm links.
14. **Better Auth admin plugin for roles and server-side user creation.** — With `disableSignUp`, the plain sign-up endpoint is blocked even server-side; the admin plugin's `createUser` works without a session when called from the server and sets `role` + `tenantId`. Roles: `agency_admin` (admin permissions), `client_admin`/`client_staff` (none inside Better Auth; app-level guards decide). — Alt: sign-up then patch the row (non-atomic).
15. **API keys use SHA-256, not a password KDF.** — Keys are 192-bit random, so brute force is not a concern; lookup is a single indexed equality.
16. **Tenant secrets bind tenant + name as AES-GCM AAD**, so a ciphertext copied to another tenant's row fails to decrypt. `v1.` prefix leaves room for key rotation (M8).
17. **Config history = append-only `tenant_configs` revisions**; import/export is the same JSON as GET/PUT `/v1/config`.
18. **`.env.example` dev secrets are refused when `NODE_ENV=production`.** — Keeps `docker compose up` zero-config locally without risking a shipped dev key.
19. **DB tests live in a separate Vitest project** (`*.db.test.ts`); each test file clones a migrated template database, so files run in parallel against a clean DB.
20. **Jobs enqueue inside the tenant transaction** (`pg-boss` `fromDrizzle(tx, sql)`), so a lead and its first-reply job commit together; no separate outbox sweeper. The app role gets DML on the `pgboss` schema; pg-boss itself runs as the owner. The `events` table keeps domain history (and feeds outbound webhooks later).
21. **One send path: `sendToLead`.** It checks opt-out, picks free-form vs template from the 24 h window (refusing anything else), refuses unapproved templates on real WhatsApp, records every attempt with an idempotency key, and calls the provider outside the transaction. Permanent failures are recorded and not retried; transient ones throw so pg-boss retries with backoff, then dead-letters. Known ceiling: a crash between the provider call and the status update can re-send (at-least-once).
22. **Opt-out suppression list stores an HMAC of the phone**, keyed with the server secret, per tenant. It survives DPDP erasure of the lead without keeping the number. Opt-out is permanent in v0.
23. **One-word opt-out keywords must be the whole message; phrases may appear anywhere.** Avoids "don't stop, I want to book" unsubscribing someone.
24. **Templates: registry in code (`packages/config/src/templates.ts`), approval status per tenant in the DB.** `docs/TEMPLATES-TO-SUBMIT.md` is generated from the registry and a test fails if it drifts. Positional variables (works with BSPs too). Submitted in `en` + `hi`; Hinglish leads get the English template.
25. **Webhook routing by Meta ids on `tenants`** (`wa_phone_number_id`, `meta_page_id`): one agency Meta app receives every client's webhooks. App secret/verify token are global env; per-tenant tokens are encrypted secrets.
26. **Hosted form is a same-origin page (`/f/:formKey`) embedded by iframe.** No CORS, consent text comes from config, honeypot + per-IP rate limit (`@fastify/rate-limit`).
27. **Duplicate submissions (same phone) don't re-send the first reply.** They update missing name/email and add a consent record. Re-engagement of old leads is the AI's job once they reply.
28. **Graph API pinned to v23.0**, matching Meta's published OpenAPI spec; bump deliberately.
29. **DB tests run on embedded-postgres (real Postgres 16 binaries from npm), not testcontainers.** — Works without Docker or admin rights (Docker Desktop is broken on the dev machine), starts faster, same on CI. `pnpm db:local` uses it for local dev too. Compose remains the deployment path. The cluster is forced to UTF-8 (Windows defaults to WIN1252, which rejects Hindi).
30. **Assistant model: `claude-sonnet-5-5` with `thinking: {type: "between_tools"}` at `effort: "low"`.** — Spec names Sonnet 5.5; it rejects disabled thinking and forced tool choice. `between_tools` = no extended thinking: short, fast WhatsApp replies. No Haiku: language detection is a deterministic word-list heuristic and intent is the agent's job, so there was nothing left for a second model.
31. **Prompt layout for caching and preserved thinking:** stable per-tenant system prompt (rules, questions, knowledge) with `cache_control`, deterministic tool list, conversation rebuilt from stored WhatsApp messages (text only), and per-turn CRM state (time, answers, missing questions) as a trailing mid-conversation `role: "system"` message. Within a turn the history is append-only (assistant content passed back unchanged).
32. **Deterministic guards before the model:** human takeover, opt-out, emergency keywords (fixed reply + takeover, no LLM call), per-lead cost cap. Refusals, 4xx API errors and the step limit all hand over to staff with a holding message in the lead's language.
33. **Scoring is code, not the model.** `record_answer` stores the answer; `scoreLead` (packages/core) computes Σ weight × option score against the thresholds and disqualifiers, and transitions the lead. Answers live in `answers`; the latest score on `leads.score` (no separate `lead_scores` history table).
34. **No server-side refusal fallbacks.** The only categories it retries (`cyber`, `frontier_llm`) are irrelevant to a clinic receptionist; any refusal goes to a human, which is the right behaviour here.
35. **Debounce + one turn per lead via pg-boss:** `assistant-turn` queue with `stately` policy and `singletonKey = leadId`, `startAfter: 3 s`. A burst of messages becomes one reply; two turns never race.
36. **Mock-mode assistant is a rule-based fake (`assistant/fake-llm.ts`)** driving the same tools, so tests, `pnpm sim` and the demo work with zero credentials. Real-model safety evals live in `assistant.eval.db.test.ts`, run only with `RUN_LLM_EVALS=1` + `ANTHROPIC_API_KEY` (they cost money).
37. **Langfuse tracing deferred** (ROADMAP). Every call is logged to `llm_runs` (tokens incl. cache, cost, latency, stop reason, request id), which covers margin tracking now.
38. **No double booking is a Postgres exclusion constraint** (`btree_gist`, `EXCLUDE (tenant_id =, resource =, tstzrange(starts_at, busy_until) &&) WHERE status is active`). The app re-checks availability in the transaction for a friendly error; the constraint is what makes a race impossible (tested with 10 concurrent bookings: exactly one wins).
39. **Availability = weekly rules per resource (chair/doctor/agent) − blocked times − active appointments (held until end + buffer)**, computed in pure code (`packages/core/availability.ts`) with time zones via `Intl` (no date library; DST-tested). New tenants start from their business hours; a migration backfills older tenants the same way.
40. **Chat offers are spread out** (earliest first, ≥ 90 min apart, preferred part of day first); the dashboard can list every free slot. The model books by local `date` + `time` it read from `get_available_slots`, so it never has to carry ISO instants across turns.
41. **One active appointment per lead**; changing it is `reschedule` (cancel + book in one transaction, so the old slot frees only if the new one succeeds).
42. **Appointment side effects run in an `appointment-notify` job**: lead message (approved `booking_pending` / `booking_confirmed` template), staff alert (WhatsApp template or email per config), Google Calendar sync. Idempotent per appointment + change.
43. **Staff can book any non-opted-out lead** (state machine: `BOOKED` allowed from `new`/`contacted` too): a patient who phones the clinic gets booked directly.
44. **Google Calendar is one-way** (our appointments → their calendar) via a refresh token stored as an encrypted tenant secret; OAuth `state` is HMAC-signed and expires in 10 minutes. Email is Resend; outside mock mode, an unconfigured email provider fails loudly instead of pretending.
45. **Messages are ordered by (occurred_at, created_at)** — with a frozen test clock (and in real bursts) business timestamps can tie.
46. **Sequence definitions live in tenant config; the DB holds `enrollments` + `enrollment_steps` only** (no `sequences` table). Steps carry a business-clock `due_at` (and an optional deadline, e.g. a reminder must go before the appointment).
47. **Scheduling = per-minute pg-boss cron sweep + one pg-boss job per due step** (key `enrollment:{id}:step:{n}` doubles as the message idempotency key). The sweep claims with `FOR UPDATE SKIP LOCKED` and re-claims steps stuck in `queued` for 10+ minutes; the job gives retries with backoff and the dead-letter queue. This is what lets the demo fast-forward: pg-boss delayed jobs alone run on real time.
48. **Send-time checks:** enrollment still active, lead not opted out, deadline not passed; quiet hours move the step to the end of the window (or skip it if that's past the deadline).
49. **Stop rules in one place** (`stopOnLeadEvent`, called from `transitionLead`): opt-out stops everything; reply / booking / disqualification stop follow-ups (honouring `sequences.followup.stop_on`).
50. **Reminders only for scheduled/confirmed appointments** (not pending staff approval); rescheduling replaces them; cancel/complete/no-show stop them; completion enrols the review request, no-show enrols recovery.
51. **Reminder buttons are handled in code:** Confirm → appointment `confirmed` + lead `confirmed` + staff alert; Cancel → appointment cancelled; "Please call me" → human takeover. Reschedule and other buttons go to the assistant as text.
52. **Silent leads are marked unresponsive 48 h after the last follow-up.** Follow-ups go by email when the step allows it and the lead gave an email.
53. **Mock mode runs on an `OffsetClock`** (real time + a forward-only shift) exposed at `POST /v1/dev/clock/advance`; it is process-wide, which is fine for a demo server and never enabled in production.
54. **Dashboard: React + Vite + Tailwind 4 + TanStack Query, no router or component library.** A ~20-line pushState router covers five pages; the handful of shadcn-style primitives live in `ui.tsx`. Plain `fetch` to Better Auth endpoints (no auth client). 99 KB gzipped.
55. **Served by the API from `apps/dashboard/dist` (same origin)** with an SPA fallback that never swallows unknown `/v1`, `/api`, `/webhooks`, `/f` paths. In dev, Vite proxies to :3000 and Better Auth trusts `http://localhost:5173` outside production. The Docker image builds the dashboard in a throwaway stage.
56. **Settings edits the whole config as forms on a draft copy**; Save sends one `PUT /v1/config` and shows the server's plain-English validation errors in the save bar; JSON import/export is the same document. Availability and template approval have their own endpoints (not config).
57. **Demo sandbox refuses to run on a tenant connected to real WhatsApp** (it would message real numbers). Template messages store their quick-reply buttons so the sandbox and inbox can show and tap them.
58. **Agency usage shows WhatsApp (estimated INR) and LLM cost per tenant this month**, from `messages.est_cost_inr` and `llm_runs.cost_usd` (LLM shown in INR at a fixed display rate).
59. **Effects always use block bodies** — newer Chromium returns a Promise from `scrollIntoView()`, which React would treat as an effect cleanup and crash.
60. **Weekly report numbers are SQL over business-clock timestamps** (`leads.received_at`, `messages.occurred_at`, `events.occurred_at` for bookings, `appointments.starts_at` for shows), never the LLM. "Revenue recovered" = completed visits × average visit value; upcoming bookings are reported separately. Topics asked about are keyword groups, not AI summaries.
61. **Reports are scheduled per tenant by an hourly cron** (and on demo fast-forward): on the configured weekday from 09:00 tenant-local, last week's report is computed, stored (unique per period, so exactly once) and emailed. WhatsApp delivery of the report is not built (ROADMAP).
62. **No `integration_health` table: health is derived** from messages, delivery receipts and `llm_runs`, so it can't drift from reality. Alerts (failed sends, AI errors, missing delivery receipts = silent webhook, queue backlog, dead-lettered jobs) run every 5 minutes, are deduped in `alerts` (re-sent at most every 6 h) and emailed to `ALERT_EMAIL`.
63. **Erasure deletes; the opt-out suppression (a keyed hash) stays**, so "forget me" never re-enables messaging. Retention defaults to anonymize (counts survive for reports) after 365 idle days; "idle" includes upcoming appointments.
64. **Outbound webhooks use the existing `events` table as the outbox** (`webhook_dispatched_at`), claimed with `FOR UPDATE SKIP LOCKED` by the per-minute sweep and fanned out into one pg-boss job per endpoint. Lead details are read at delivery time, so erased leads send ids only. Signature format follows the common `t=,v1=` HMAC scheme.
65. **Key rotation keeps a key ring** (`SECRETS_KEY` + optional `SECRETS_KEY_PREVIOUS`) for decryption; a script re-encrypts. Phone hashes and OAuth state use a separate `HASH_KEY` (defaults to `SECRETS_KEY`) that must never rotate, because opt-out hashes can't be recomputed without the phone.
66. **Per-item queues (first reply, sequence steps, appointment notifications, webhooks) poll at 0.5 s in batches of 10 with per-job results** (first replies in parallel, the rest in order per batch) rather than pg-boss LISTEN/NOTIFY: with NOTIFY the 30 s backstop poll dominated under load (p95 198 s in the test), while fast batched polling gave p95 0.5 s for 100 leads in 20 s at the cost of ~2 cheap queries/s idle.
67. **The demo is an HTTP script, not a test**: it creates fresh tenants through the agency API and drives the live app (workers, crons, dev clock), so it proves the deployed wiring, not just the functions. Scenario 4 jumps to a Monday so the report week is deterministic.
68. **Production sits behind Caddy** (automatic TLS) with the app port closed and `TRUST_PROXY=true`; one VPS in an Indian region.
69. **Webhook SSRF guard in production**: the URL's host must resolve only to public addresses (no loopback, RFC 1918, CGNAT, link-local / cloud metadata, IPv6 ULA / link-local, IPv4-mapped), checked on save and before every delivery; redirects are not followed. Off outside production so local receivers work.
70. **CSP**: the dashboard is fully same-origin (`default-src 'self'`, no framing); the hosted form gets its own policy (no scripts, inline styles, `frame-ancestors *` so clinics can iframe it).
